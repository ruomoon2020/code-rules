# 受监管 Web 前端加固

本文适用于金融、政务和高敏数据后台，作为条件规则使用，不进入 Level 0。

## 浏览器边界

1. 浏览器防护策略须由网关、CDN 或服务端配置并在生产响应中验证；仅写前端 meta 不算完成。
2. 宽泛脚本执行和通配域确需例外时，须有 Owner、影响范围、到期日和替代计划。
3. 富文本、动态 HTML 和脚本注入场景须保留统一的内容消毒边界。
4. 外部静态资源应固定可信来源和版本，并明确资源不可用时的降级行为。

## 第三方脚本与数据流

1. 第三方脚本接入前须登记 Owner、来源、版本、加载时机、采集字段、出站域、隐私依据、退出清理和替代方案。
2. 禁止从接口字段、URL 参数或用户输入动态拼接脚本地址并执行；第三方脚本只允许来自项目白名单。
3. 非首屏必需脚本延后加载；加载失败不得阻断登录、权限校验和核心业务操作。
4. 第三方脚本升级须复核数据流、体积、权限和行为变化，并对核心路径回归。

## 嵌入页面与跨窗口通信

1. 嵌入页面目标域须白名单化并设置最小能力；禁止内嵌未知来源页面。
2. 跨窗口消息发送端指定精确来源，接收端校验来源窗口、来源域和消息结构；禁止生产通配放行。
3. 跨窗口消息不得直接驱动转账、审批、权限变更、下载敏感数据等高风险动作；须回到受信接口重新校验状态和权限。
4. 页面嵌入与被嵌入策略须与登录态和单点登录方案一致。

## 会话与高风险操作

1. 浏览器会话策略和跨站请求防护须与后端共同确认；前端不得自行弱化策略绕过联调问题。
2. 支付、审批、权限变更、明文导出等操作须根据项目策略重新认证或二次确认，最终放行以后端状态为准。
3. 前端缓存不得保存超出页面生命周期所需的高敏数据；退出、切换租户和权限收回后须清理。
4. 远程配置和高风险开关失败时使用安全默认值，并具备 Owner、回滚、观察指标和清理日期。

## 构建与验证

1. 生产构建须检查 mock、调试入口、公开 sourcemap、非白名单域和不安全响应头；浏览器实际响应证据须进入发布记录。
2. 第三方脚本、嵌入页面或跨窗口通信改动须覆盖来源校验、失败降级、敏感字段出站和权限回归测试。
3. 高风险项目至少执行依赖检查、响应头验证、关键路径 E2E 和数据分级复核。
4. 无法自动验证的策略须记录人工步骤、环境、结果、Owner 和复查日期，不得仅写“已检查”。
