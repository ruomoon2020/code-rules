# 表单与详情页规则

表单页、详情页的补充约束（列表页见 `04-ui-patterns.md`）。

## 表单

1. 字段必须来自权威契约 `contracts/openapi.yaml` 及其同步生成的类型；禁止凭空增加，也禁止手改生成物补字段。
2. 必填、长度、格式、枚举必须与契约一致。
3. 异步校验必须有 pending / loading 反馈。
4. 提交失败必须保留用户输入；禁止在失败回调中重置表单、关闭弹窗或覆盖草稿。
5. 并发控制按以下流程处理：
   - 更新和删除请求必须携带页面当前保存的 `version`；提交前不得重新查询详情并替换该值。
   - 收到 `CONCURRENT_MODIFICATION` 或契约声明的等价错误码后，保留用户输入，提示数据已变化，并提供刷新或对比入口。用户确认前不得覆盖提交。
   - 创建成功后保存响应中的初始 `version`；更新成功后以响应中的新 `version` 覆盖本地值，供下一次提交使用。
6. 只读详情必须使用只读语义，避免用可编辑表单样式误导用户。
7. 大表单优先 Drawer 或分步，避免小弹窗塞满字段。

## 详情页

1. 结构建议：页头 + 描述列表（Descriptions）+ 操作区 + 关联 Tab（若有）。
2. 展示字段必须与权威 OpenAPI 契约及其同步生成类型一致；敏感字段必须按数据分类和权限脱敏，禁止因详情页只读而展示完整敏感值。
3. 时间、金额、状态必须走 `utils/format` 与统一状态标签。
4. 审计日志、操作记录按模块需求展示，不阻塞主信息。

## 字段状态

- 禁用须表达原因（tooltip / 文案）。
- 依赖字段联动时，清除无效联动值。

执行以本文件、`12-schema-ssot.md` 与业务仓现有 Base 表单 / 详情组件为准。
