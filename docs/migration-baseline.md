# 目标规则与存量迁移基线

> 用于把高于现状的通用规范接入已有项目。它不降低目标规则，也不把存量代码伪装成已经合规。

## 两套事实必须分开

- **目标规则**：新代码、被实质修改的代码和新架构决策必须遵守的最终标准。
- **当前基线**：接入时通过机器扫描得到的存量偏差，只用于阻止债务增长。
- 项目覆盖层只能声明真实路径、技术栈、命令、兼容窗口与例外，不能静默改写通用目标。
- 若目标规则与当前实现冲突，记录迁移项；不得删除目标规则，也不得声称存量已经通过。

## 基线约束

1. 基线由可复现命令生成或核对，并绑定提交、日期、责任人和扫描配置。
2. 数量型指标只允许持平或下降；路径白名单只允许删除，不允许新增。
3. 修改命中存量债务的文件时，至少不得扩大债务，并优先在同一改动中收敛。
4. 规则、扫描范围、匹配表达式或构建产物变化时，必须人工审阅基线影响。
5. 例外必须记录原因、责任人、到期时间、补偿控制和退出条件。

## CI 双通道

| 通道 | 作用 | 失败语义 |
|---|---|---|
| 当前采纳门禁 | 校验已声明成熟度与债务基线 | Required，失败阻断 |
| 目标差距审计 | 展示更高成熟度尚缺内容 | 报告模式，不伪装为已通过 |

报告模式只能改变退出码，输出仍须明确标记为 `TARGET GAPS`。CI 摘要要同时展示当前采纳级别、目标级别和差距，禁止用 `continue-on-error` 隐藏检查失败。

## 基线配置最低字段

基线 JSON（见 `examples/migration-baseline.json`）至少包含：

| 字段 | 说明 |
|---|---|
| `version` | 固定为 `1` |
| `baseline_commit` | 生成或核对基线时的完整 Git commit SHA |
| `captured_at` | ISO-8601 时间（须含时区，如 `2026-09-15T12:00:00+08:00`） |
| `owner` | 基线责任人（账号或角色） |
| `scan_command` | 可复现扫描命令 |
| `metrics` | 非空指标列表（`regex-count` / `path-allowlist`） |

`scripts/check-debt-baseline.py` 会校验上述元数据；缺少任一字段即失败。

每个指标默认至少须命中 1 个文件；零命中会失败，防止目录迁移或 glob 写错后被误判为债务清零。确实允许空扫描的指标须显式设置 `minimum_files: 0` 与不少于 8 个字符的 `allow_empty_reason`，并由 Owner 审阅。报告会输出 `files_scanned`。

## 机器输出最低字段

- 指标名、扫描根、匹配范围与配置来源。
- baseline、current、delta；路径白名单还需 added、removed。
- 扫描命令、退出码和执行提交（由 CI 日志与基线元数据共同留痕）。
- 例外或跳过项及其原因。

通用样板见 `examples/migration-baseline.json`；项目路径与实际阈值应放在业务仓，不回写到通用规则。
