# 架构师代码与工程规范 Checklist

> 适用场景：新项目立项评审、技术方案评审、上线前检查、团队规范落地。
> 使用方式：复制到评审记录；勾选结论写「通过 / 豁免 / 不适用」，豁免须走 [`rule-exception-process.md`](rule-exception-process.md)。
> 合并与发布的强制门禁以 [`definition-of-done.md`](definition-of-done.md) 为准。本清单是评审提问单，不替代各端 `rules/shared/`。

规则列写的是本仓库路径。第一至第八节里只有编号的条目，均指 `web-backend/rules/shared/` 下同号文件，不指管理端或小程序的同号文件。第九节写各端完整路径。业务仓未安装对应规则包时，仍按检查点判断，忽略缺失的文件路径。

## 一、架构与设计

| # | 检查项 | 检查点 | 落地建议 | 规则 |
|---|---|---|---|---|
| 1.1 | 分层架构 | 是否明确 Controller / Service / DAO，或六边形 / Clean 分层 | 禁止跨层调用。已接入 ArchUnit 或等价架构测试时，用它卡住依赖方向；未接入须在项目中说明，不能把推荐项当成所有仓库的合并条件 | `01-project-structure.md`、`15-testing.md`；[`definition-of-done.md`](definition-of-done.md) |
| 1.2 | 模块边界 | 模块职责是否单一，跨模块是否只走公开接口 | 按限界上下文划分；禁止跨模块直接改对方的表或内部类型 | `43-business-module-extension` |
| 1.3 | 依赖方向 | 是否存在循环依赖、反向依赖 | 依赖只能指向更稳定的内侧。已接入架构测试或依赖检查时用它卡住方向；未接入须说明，不能把某个工具当成所有仓库的必做项 | `01-project-structure.md`、`15-testing.md` |
| 1.4 | 接口契约 | 是否有版本、入参出参、错误码和破坏性变更策略 | OpenAPI 为单一来源。入参和出参用传输对象，禁止把持久化实体直接当接口。消费端生成代码，禁止手改 `generated/**` | `04-rest-api-design.md`、`05-openapi-contract.md`、`12-dto-mapping.md`；[`definition-of-done.md`](definition-of-done.md) §契约 |
| 1.5 | 幂等与并发 | 支付、导入、批量变更是否有幂等键；更新是否防丢失；分布式锁是否会拖住业务 | 重复请求返回同一业务结果或明确冲突码；唯一索引 + 乐观锁，禁止先查再插。分布式锁只锁短临界区，必须有过期时间，释放时校验持有者 | `18-idempotency-concurrency` |
| 1.6 | 领域模型 | 业务规则放在哪里；聚合根由谁修改 | 规则放在实体或领域服务；聚合根只经应用服务修改；实体不出 API。充血不是把 HTTP 和持久化塞进实体 | `11-domain-model` |
| 1.7 | 扩展点 | 多实现、多租户差异、渠道差异是否有稳定扩展点 | 只有确有多个实现时才预留 SPI / 插件；写明负责人和删除条件。单条业务不要为扩展而抽象 | `43` |
| 1.8 | 配置与密钥 | 多环境是否隔离；密钥是否进仓库 | 配置中心或环境变量；密钥走 KMS / Vault，可轮换；禁止硬编码 | `21-configuration-secrets` |
| 1.9 | 事务边界 | 本地事务里是否调用了外部系统 | 事务内禁止同步 HTTP / RPC，以及无法与数据库一起回滚的消息发送；跨服务用 Outbox 或事务消息 | `18`、`17`、`39-event-contracts` |
| 1.10 | 金额、时间、状态 | 金额精度、时区、状态流转是否统一 | 禁止用浮点数表示金额；写明币种、舍入和时区；状态用显式状态机，禁止散落判断 | `40-money-time-precision`、`41-dictionary-state-machine` |
| 1.11 | 接口形态 | 是否返回持久化实体；排序和筛选是否白名单；是否引入非 HTTP 接口 | 入参和出参用传输对象。排序、筛选字段白名单。图查询、远程调用、长连接须先写决策记录。图查询要限制深度和复杂度，生产关闭随意的结构探测。长连接见 9.14 | `12-dto-mapping.md`、`19-pagination-query.md`、`33-alternate-api-paradigms.md` |
| 1.12 | 定时与批处理 | 任务是否防重、可恢复、可关闭 | 多实例不得重复执行。重试不得重复扣款或重复发消息。分批提交，禁止一批事务包住海量数据。任务有负责人、超时、告警和关闭开关。任务不能绕过权限、租户、审计和脱敏 | `25-jobs-scheduling.md` |

## 二、非功能需求

| # | 检查项 | 检查点 | 落地建议 | 规则 |
|---|---|---|---|---|
| 2.1 | 性能指标 | 核心接口是否有延迟和吞吐预算 | 上线前有压测基线；超预算进入发布风险评审，禁止只把超时调大 | `16-performance`、`32-service-reliability` |
| 2.2 | 依赖韧性 | 关键外部依赖是否有超时、熔断、限流、降级 | 降级返回可理解的错误码。按能力选型，不绑定已停止维护的具体库 | `28-external-integration`、`32` |
| 2.3 | 限流隔离 | 是否有接口级、租户级限流和舱壁 | 按接口、租户或连接池隔离。具体算法由网关或限流组件实现。失败时拒绝，而不是拖垮进程 | `32-service-reliability.md`、`28-external-integration.md` |
| 2.4 | 可观测性 | 日志、追踪、指标是否齐全 | `traceId` 贯穿全链路。核心接口至少看请求速率、错误率和延迟。日志无令牌和个人信息明文 | `09-logging-observability.md` |
| 2.5 | 告警与值班 | 是否分级，是否有人负责 | P0 核心不可用、P1 核心降级、P2 非核心；告警带追踪号、服务、版本；有值班表 | `32`；`docs/slo-alerting-template.md` |
| 2.6 | 认证、授权与越权 | 是否同时覆盖登录、功能权限、数据范围和对象级越权 | 前端隐藏按钮不能代替后端鉴权。列表、详情、导出、批量操作使用同一套数据权限。必测未登录、无权限、跨租户、拿他人 ID 访问 | `06-security-authz.md`、`24-data-access-cache.md` |
| 2.7 | 数据分级与脱敏 | 新字段是否分级；日志、缓存、导出、消息是否按级处理 | 对照分级矩阵。脱敏组件不能只加在列表页 | `docs/data-classification-matrix.md`、`29` |
| 2.8 | 一致性 | 跨服务写操作的一致性方案是否写明 | 优先本地事务 + Outbox 和补偿；跨库禁止用一个本地事务假装分布式事务 | `18`、`39` |
| 2.9 | 威胁建模 | 登录、支付、权限、导入导出、Webhook、个人信息变更是否做了轻量威胁建模 | 记录资产、信任边界、入口、滥用场景、缓解和剩余风险负责人 | `35-threat-modeling` |
| 2.10 | 审计 | 敏感操作能否回答谁在何时做了什么 | 审计含操作者、追踪号、对象和前后状态；禁止只打一条「操作成功」 | `27-audit-log` |
| 2.11 | 服务间认证 | 内部调用是否证明调用方身份 | 不信任内网地址；服务间授权不能绕过租户和数据权限 | `37-service-to-service-auth` |
| 2.12 | 恢复目标 | 是否声明可接受的数据丢失窗口和恢复时间 | 数据库、消息、对象存储的备份与目标一致；没做过恢复演练，不得声称可随时恢复 | `32`、`31-production-data-ops` |
| 2.13 | 错误预算 | 可用性未达标时是否会停掉无关发布 | 对外承诺不得高于内部目标；错误预算烧完优先修稳定性和观测 | `32` |
| 2.14 | 功能开关 | 开关是否有负责人和到期日 | 灰度开关到期删除代码和配置，禁止长期留在主干 | `21` |
| 2.15 | 密码、令牌与密钥 | 密码如何存储；令牌是否校验；密钥能否轮换 | 密码只用带盐慢哈希。令牌校验签名、过期、签发方和受众。登出、改密、冻结后旧会话失效。密钥有负责人、轮换和吊销，禁止自研算法 | `36-crypto-key-management` |
| 2.16 | 回调与重放 | Webhook 和外部回调能否被伪造或重放 | 校验签名、时间戳和随机数或幂等键 | `36`、`37` |
| 2.17 | 出站请求 | 用户能否指定服务端去访问的地址 | 出站地址走白名单，禁止把用户输入直接当作请求目标 | `28-external-integration` |
| 2.18 | 会话与暴露面 | 跨域、Cookie、管理端点在生产是否收口 | 生产禁止任意源带凭据。Cookie 会话启用跨站防护。接口文档和除健康检查外的管理端点不对公网开放 | `06`、`22-operability` |
| 2.19 | 登录防刷 | 登录、验证码、重置密码是否限流 | 按 IP、账号或租户限流；错误提示不暴露账号是否存在 | `06` |

## 三、数据与存储

| # | 检查项 | 检查点 | 落地建议 | 规则 |
|---|---|---|---|---|
| 3.1 | 数据库规范 | 命名、索引、字段类型是否统一 | 建表模板 + 评审；金额列写明精度，多租户唯一约束带租户键 | `07-persistence-mybatis`、`02-naming` |
| 3.2 | 索引与查询 | 是否避免全表扫描、深分页，以及把用户输入拼进排序 | 慢查询监控 + 执行计划审查；排序和筛选走白名单 | `07`、`19-pagination-query` |
| 3.3 | 分片 | 是否要分库分表；分片键是否写进决策记录 | 分库分表、索引重构和跨库迁移须先有决策记录，写明容量、分片键、迁移和回滚。分片键要能覆盖主要查询 | `30-ownership-adr.md` |
| 3.4 | 读写分离 | 写完立刻读的路径是否会读到从库旧数据 | 创建后立即详情、支付后查单等路径必须写明是否读主库。从库延迟要监控，超过阈值告警或改读主库。事务内读写走同一连接 | `07-persistence-mybatis.md` |
| 3.5 | 缓存防护 | 穿透、击穿、雪崩是否有对策 | 空值缓存、互斥、随机过期按场景选用，不默认三件套全上 | `24` |
| 3.6 | 缓存一致性 | 更新策略、失效和租户维度是否写明 | 写明是旁路缓存还是其他策略，以及 TTL。缓存键和值不得带明文个人信息 | `24`、`29` |
| 3.7 | 结构迁移 | 是否版本化，新旧版本能否同时运行 | Flyway / Liquibase；先扩展再收缩，保证滚动发布期间新旧代码都能读写；禁止手工改表 | `07`；`docs/definition-of-done.md` §数据 |
| 3.8 | 消息 | 顺序、重复、死信、契约版本是否处理 | 幂等消费 + 死信 + 有界重试；事件像接口一样管理版本和兼容 | `17`、`39` |
| 3.9 | 保留与删除 | 是否有保留周期、注销和个人信息删除 | 软删除要说明何时物理清理；注销后对外接口不得再返回可识别个人信息 | `29`、`34-data-archival` |
| 3.10 | 生产数据操作 | 手工 SQL、回填、从生产复制数据是否可审批 | 工单、影响范围、预演、回滚、审计；条件必须带主键、租户或时间窗 | `31` |
| 3.11 | 备份恢复 | 备份是否加密、限权，并做过恢复演练 | 证明「能恢复」，而不是只证明「有备份」 | `31`、`32` |
| 3.12 | 多数据库 | 若同时支持多种数据库，迁移和核心 SQL 是否都跑过 | 每种目标库都做迁移校验和核心用例，禁止只在一种库上通过 | `07`、`15` |
| 3.13 | 字典与主数据 | 枚举和主数据是否只有一处来源 | 前后端共用契约里的枚举；禁止各端各写一套魔法值 | `41` |
| 3.14 | 租户配额 | 多租户是否限制单租户的请求、存储或批处理量 | 配额超限有明确错误码，不能靠把线程池打满来限流 | `24` |
| 3.15 | 冷热数据 | 在线接口是否会把归档数据一起扫进来 | 在线接口默认只查仍在主路径上的热数据，避免历史大表拖慢主库。查归档走单独接口和权限，并写清是否异步导出。禁止对大表做无分批的全表删除。归档存储必须鉴权，不能公开访问 | `34-data-archival` |

## 四、代码质量与工程化

| # | 检查项 | 检查点 | 落地建议 | 规则 |
|---|---|---|---|---|
| 4.1 | 项目结构 | 目录是否与脚手架一致 | 统一脚手架；新模块走扩展规则，不另起一套目录 | `01` |
| 4.2 | 命名 | 类、方法、变量、表和字段是否可读 | 检查器强制。金额字段带语义和单位，禁止 `money`、`price1` 这类名字 | `02` |
| 4.3 | 注释 | 是否解释为什么，而不是复述代码 | 复杂 SQL、权限、多库兼容、金额和时区语义必须写清。公开契约写在 OpenAPI，不靠类注释堆历史 | `03-code-style` |
| 4.4 | 变更记录 | 作者、日期、版本从哪里查 | 以 Git 历史和变更日志为准。不要求文件头再写作者、日期、版本 | `docs/git-pr-governance.md` |
| 4.5 | 异常与错误码 | 是否统一异常体系和错误码 | 业务异常加全局处理。错误码用 `DOMAIN_REASON` 全大写下划线，集中放在枚举或常量里，例如 `USER_NOT_FOUND`。未知异常映射为 `INTERNAL_ERROR`，不把堆栈返回给客户端 | `08-exception-errorcodes.md` |
| 4.6 | 输入校验 | 是否防批量赋值和越权字段 | 更新请求只含允许修改的字段；角色、租户、状态不能从普通更新接口写入 | `13-validation` |
| 4.7 | 静态扫描 | 严重问题是否阻断合并 | 质量门禁阻断严重缺陷；跳过须记录豁免 | `23-quality-gates` |
| 4.8 | 依赖 | 版本是否锁定；漏洞和许可证是否扫描 | 用父 POM 或 BOM 对齐版本，禁止无回归地升级主版本。高危漏洞按处置时限。GPL / AGPL / 未知许可证须评审。发布制品的软件物料清单见 7.5 | `20-dependency-governance.md`；[`supply-chain-baseline.md`](supply-chain-baseline.md) |
| 4.9 | 代码审查 | 谁必须看哪类变更 | 受保护分支只走拉取请求。契约、数据库、安全、持续集成按所有者矩阵审查，不能只数人数 | `docs/codeowners-matrix.md`、`docs/git-pr-governance.md` |
| 4.10 | 文件导入导出 | 上传、导入、下载是否有边界 | 校验类型和大小。导入有行数上限、幂等和行列级失败明细。下载链接鉴权并设有效期，禁止永久公开地址 | `14-file-import-export` |

## 五、测试

| # | 检查项 | 检查点 | 落地建议 | 规则 |
|---|---|---|---|---|
| 5.1 | 单元与分支 | 核心逻辑的分支、异常和权限失败是否覆盖 | 项目覆盖层定义阈值并关注新增代码与趋势；生成代码等排除项须显式配置。覆盖率不能代替有效断言，核心域可条件启用变异测试 | `15-testing` |
| 5.2 | 边界 | 空值、极值、金额、时区、编码和超量输入是否覆盖 | 参数化测试；覆盖金额舍入、月末/年末、Unicode、超长文本、大文件和大分页。解析器、规则引擎等高风险模块可用属性测试或模糊测试 | `15`、`40` |
| 5.3 | 集成 | 数据库、缓存、消息和外部依赖是否在隔离环境联调 | 使用与生产行为一致的容器、嵌入式依赖或等价临时环境；禁止连生产和预发。异步与跨线程用例显式清理，不能只依赖测试事务回滚 | `15` |
| 5.4 | 契约 | 接口、事件和文件契约是否兼容消费者 | OpenAPI diff + 消费端生成代码校验；独立部署服务按风险启用消费者驱动契约；MQ、Webhook 和批量文件也要有版本与兼容策略 | `05`、`15`、`39-event-contracts` |
| 5.5 | 回归 | 合并请求和发布是否运行匹配风险的回归集 | PR 跑快速确定性回归；发布分支跑集成、端到端、安全和迁移回归；定时跑跨平台或长时间测试。Required 失败禁止合并 | `23`；`docs/branch-protection.md` |
| 5.6 | 性能 | 是否有可复现的压测基线，并纳入高风险发布 | 记录数据量、并发/QPS、预热与时长、P50/P95/P99、错误率、资源水位和基线差异；预算超标进入风险评审 | `16` |
| 5.7 | 安全测试 | 越权、注入、依赖和敏感凭据是否在流水线里 | PR 跑静态、依赖、凭据及鉴权/跨租户回归；有可部署环境时跑 DAST/API 模糊测试；人工渗透按风险或大版本启用 | `06`、`15`、`23` |
| 5.8 | 故障演练 | 是否验证过依赖失败、降级和数据恢复 | 演练声明稳态、影响半径、中止条件和恢复目标，并记录 RTO/RPO 与改进行动。Chaos Mesh 等只是可选注入手段 | `32`、`31` |
| 5.9 | 测试数据 | 是否可重复、可隔离、可清理且无生产个人信息 | 优先 synthetic fixture；生产数据须脱敏与审批。按用例/租户隔离，失败后可清理；性能数据达到目标数量级 | `15`、`29` |
| 5.10 | 测试稳定性 | 用例是否可重复，是否靠重试掩盖偶发失败 | 固定时钟、随机种子、网络响应和运行版本；监控 flaky rate。隔离用例须有 Owner、原因和到期日，禁止无限重试把红灯洗绿 | 各端 testing 规则；`docs/rule-exception-process.md` |
| 5.11 | 并发与幂等 | 重复提交、并发更新、重复消费和乱序到达是否验证 | 覆盖幂等键、唯一约束、乐观锁冲突、任务多实例防重、消息重复投递和重放 | 后端 `18`、`25`；各端 testing 规则 |
| 5.12 | 兼容与迁移 | 新旧版本并存、数据库迁移和事件升级是否可用 | 覆盖 N/N-1、滚动升级、事件 Schema 和 expand/migrate/contract；验证可重入迁移及前滚/回滚策略 | `05`、`07`、`39`；[`environment-promotion.md`](environment-promotion.md) |
| 5.13 | 失败诊断证据 | CI 失败后能否直接定位原因 | 保留测试报告、原始输出和 run/test id；有请求上下文时再关联 traceId。端侧按需保留截图、视频、网络记录。证据须脱敏并按期限保存 | 各端 testing / observability 规则；[`requirements-traceability.md`](requirements-traceability.md) |

## 六、文档与协作

| # | 检查项 | 检查点 | 落地建议 | 规则 |
|---|---|---|---|---|
| 6.1 | 架构决策 | 关键选型是否有记录 | 每个重大决策一篇决策记录：背景、选项、后果 | `30-ownership-adr` |
| 6.2 | 架构图 | 若项目已有架构图，图是否还和当前边界一致 | 有图就和代码一起更新。仓库不强制某一种画法。重大边界变化记在决策记录里 | `30-ownership-adr.md` |
| 6.3 | 接口文档 | 是否由契约生成并在合并时检查差异 | OpenAPI + 流水线发布；破坏性变更写兼容、迁移和回滚 | `05` |
| 6.4 | 需求追踪 | 需求、验收条件、实现和验证是否能对上 | 拉取请求写明需求编号、验收条件和证据 | `docs/requirements-traceability.md` |
| 6.5 | 业务正确性 | 行为变更是否经过人工业务评审 | 流程、数据、权限、契约和回归由人看过，不把测试通过当成业务正确 | `docs/business-correctness-review.md` |
| 6.6 | README 与运维手册 | 是否能按文档把项目跑起来，并完成部署、回滚、排障 | 上手文档用各端 `docs/onboarding-new-project.md`。备份恢复手册目前只在 `web-backend/rules/docs/backup-restore-runbook.md`，其他端没有同名文件时，把恢复步骤写进该后端手册或项目自己的运维文档 | 各端 onboarding；后端 `docs/backup-restore-runbook.md` |
| 6.7 | 技术债 | 存量债务是否只减不增 | 机器基线记录当前债务；新代码按目标规则，禁止为了迁就存量去改共享规则 | `docs/migration-baseline.md` |
| 6.8 | 豁免 | 跳过门禁是否有期限和补偿 | 写明负责人、到期日、补偿措施和关闭证据 | `docs/rule-exception-process.md` |
| 6.9 | 事故 | 是否有响应路径和复盘 | 分级、沟通、证据保全；复盘含时间线、根因、行动项和关闭人 | `docs/incident-response.md`、`docs/incident-postmortem-template.md` |
| 6.10 | 合规留痕 | 金融或政务是否留下可审计证据 | 使用合规证据日志，不能只凭安全测试通过 | `docs/compliance-evidence-log.md` |

## 七、持续集成与发布

| # | 检查项 | 检查点 | 落地建议 | 规则 |
|---|---|---|---|---|
| 7.1 | 流水线 | 构建、测试、扫描是否自动执行 | 必需检查失败不能合并；流水线权限最小化，动作版本钉死 | `23`；`docs/branch-protection.md` |
| 7.2 | 分支策略 | 是否统一，主干是否受保护 | 选定一种分支模型后全仓遵守；受保护分支禁止直推 | `docs/git-pr-governance.md`、`docs/branch-protection.md` |
| 7.3 | 提交说明 | 是否能看出变更意图 | Conventional Commits；破坏性变更写迁移和回滚 | `docs/git-pr-governance.md` |
| 7.4 | 版本 | 是否语义化，变更日志是否经人看过 | SemVer。自动生成的变更日志仍由发布负责人审阅破坏性变更 | `docs/git-pr-governance.md` |
| 7.5 | 镜像与制品 | 是否最小、非 root，并有物料清单和来源证明 | 多阶段构建；禁止 `latest`；镜像内不带密钥。CPU 和内存必须有请求值与上限。二级及以上生产制品生成物料清单和构建证明 | `38-cloud-native-runtime`；`docs/supply-chain-baseline.md`、`docs/release-evidence.md` |
| 7.6 | 发布策略 | 核心域是否灰度或金丝雀 | 按业务风险选择；开关有负责人和到期日 | `32`、`21`；`docs/environment-promotion.md` |
| 7.7 | 回滚 | 是否能退回上一制品和配置 | 回滚路径可执行，并在等价环境演练过。数据结构在滚动期间兼容。只有「可以回滚」的描述、没有演练证据，不能进入生产 | [`environment-promotion.md`](environment-promotion.md)、[`release-evidence.md`](release-evidence.md) |
| 7.8 | 环境晋级 | 开发、测试、预发、生产是否隔离 | 同一不可变制品晋级；配置漂移有证据；禁止用本机直连生产库发布 | `docs/environment-promotion.md` |
| 7.9 | 密钥扫描 | 提交和流水线是否扫描凭据 | 发现即阻断，并按安全策略轮换 | `docs/supply-chain-baseline.md` |
| 7.10 | 发布证据 | 生产发布是否留下可校验记录 | 范围、风险、制品摘要、回滚验证、负责人 | `docs/release-evidence.md` |
| 7.11 | 运行探针 | 进程是否能被判定为存活、就绪，并优雅停机 | 提供存活和就绪检查。停机前处理完进行中的请求。连接池和线程池有监控。探针以外的管理端点不对公网开放 | `22`、`38` |

## 八、团队与流程

| 8.2 | 规范落地 | 能自动检查的是否已经进流水线 | 工具能挡住的不靠人口头提醒；例外走豁免单 | `23`；`docs/rule-exception-process.md` |

## 九、端侧

服务端检查通过，不代表管理端和小程序可以上线。

| # | 检查项 | 检查点 | 落地建议 | 规则 |
|---|---|---|---|---|
| 9.1 | 管理端安全与无障碍 | 是否消毒富文本；键盘、读屏、焦点是否可用 | 目标 WCAG 2.2 AA；禁止裸 `v-html`；状态不能只靠颜色 | `web-front/rules/shared/07` |
| 9.2 | 管理端失败恢复 | 脚本加载失败和白屏是否能恢复 | 有错误边界和可重试提示 | `web-front/rules/shared/21` |
| 9.3 | 国际化与时区展示 | 文案、数字、日期是否随区域变化 | 展示时区与接口时区一致，不在浏览器本地时区里隐式改业务日 | `web-front/rules/shared/23`；后端 `40` |
| 9.4 | 导入导出 | 导出是否脱敏、限权、防公式注入 | 列表脱敏了，导出、打印、剪贴板也要按同一分级 | `web-front/rules/shared/14`；`docs/data-classification-matrix.md` |
| 9.5 | 小程序体积与分包 | 主包是否超预算，分包是否按路由拆 | 体积检查进流水线 | `miniapp/rules/shared/10`、`07` |
| 9.6 | 隐私与权限 | 弹窗声明是否和实际采集一致 | 不把令牌和证件写入本地存储 | `miniapp/rules/shared/09` |
| 9.7 | 支付与内容 | 金额是否以后端为准；用户内容是否审核 | 客户端价格只展示；用户生成内容先审后发或有敏感词策略 | `miniapp/rules/shared/14`、`23` |
| 9.8 | 弱网 | 断网、分包失败、请求超时是否可恢复 | 有离线或失败提示，禁止无限重试打满流量 | `miniapp/rules/shared/22` |
| 9.9 | 管理端路由与登出 | 菜单隐藏是否等于无权限；登出是否清掉本地状态 | 路由权限与后端一致。登出清空持久化状态，敏感字段不进本地存储 | `web-front/rules/shared/06` |
| 9.10 | 小程序出站 | 请求、上传、下载和内嵌页是否只走白名单 | 生产使用加密传输。域名与平台后台配置一致，禁止页面拼接任意主机 | `miniapp/rules/shared/21` |
| 9.11 | 管理端页面与契约 | 页面是否具备基本状态；类型是否来自契约 | 加载、空、错误、无权限都要有界面；危险操作要确认。`views` 禁止直接使用 `el-*` 或从 Element Plus 引入组件，走项目的 `Base*` 组件。页面走统一请求封装，禁止直接 `axios` / `fetch`。表单和表格用生成类型，禁止手改 `generated`；未知枚举有兜底。生产包不含 mock、调试入口和公开 sourcemap | `web-front/rules/shared/00-must-follow.md`、`05-api-contract.md`、`12-schema-ssot.md` |
| 9.12 | 管理端列表 | 筛选、翻页和删除是否会串数据 | 筛选或改每页条数回到第一页。过期请求不能覆盖新结果。删除当前页最后一条要退回上一页 | `web-front/rules/shared/19` |
| 9.13 | 管理端性能 | 首屏是否被重型依赖拖住 | 有体积预算。图表、地图、富文本按需加载，不打进主包 | `web-front/rules/shared/07` |
| 9.14 | 长连接 | 实时通道是否鉴权并可恢复 | 握手鉴权，禁止把长期令牌放在 URL 上。心跳、断线重连要有退避上限，并按租户隔离。消息不能把服务端 HTML 或脚本直接插入页面 | `web-front/rules/shared/24-realtime-rich-content.md`；`web-backend/rules/shared/33-alternate-api-paradigms.md` |
| 9.15 | 受监管前端 | 金融或政务页面是否把防护做在浏览器里就算完成 | 内容安全策略由网关或服务端下发并在生产响应里验证。第三方脚本登记来源、采集字段和退出清理。跨窗口消息校验来源，不能直接驱动支付、审批或改权限。高风险操作二次确认，最终以后端为准 | `web-front/rules/shared/25` |
| 9.16 | 小程序请求与登录 | 页面是否直连平台接口；登录失效后能否恢复 | 页面禁止直接 `uni.request`。生产包不含 mock、测试账号、调试入口和公开 sourcemap。登录过期、拒绝授权、解绑后要能重新授权 | `miniapp/rules/shared/00`、`05`、`06` |
| 9.17 | 小程序支付、订阅与分享 | 支付中间态、订阅和分享是否把敏感数据带出 | 失败、取消、超时、处理中分开处理。订阅由用户动作触发，模板集中管理。分享参数走白名单，禁止携带令牌、手机号和详细地址 | `miniapp/rules/shared/14` |
| 9.18 | 小程序环境与入口 | 体验版和审核版会不会打到生产；外来入口是否重新校验 | 体验版和审核版禁止连接生产接口和生产商户号。审核演示开关默认关闭，发版前验证已关。分享、扫码、场景值进入敏感页时重新校验参数和登录态。远端开关失败时用安全默认值。第三方 SDK 登记采集字段，退出后清理 | `miniapp/rules/shared/19-release-ops.md`、`20-app-runtime.md`、`26-security-hardening-risk.md` |
| 9.19 | 小程序多平台 | 平台差异是否散落在页面里 | 登录、支付、分享、隐私等差异走适配层。页面不能用条件编译绕过这些校验。能力矩阵写在项目文档里 | `miniapp/rules/shared/11-platform-differences.md` |

## 十、一页纸速查

立项或上线评审时间不够时，至少问完下面这些。任一答不出，就不要在结论里写「通过」。

| # | 问题 | 通过标准 |
|---|---|---|
| 1 | 谁拥有这块业务，改契约和改表要谁一起看？ | 有负责人；契约、数据库、安全按所有者矩阵审查 |
| 2 | 用户拿别人的 ID、跨租户，能不能读到或改到数据？ | 后端有数据范围校验，并有越权测试 |
| 3 | 金额用什么类型，时区和账期边界是什么？ | 不用浮点数；币种、舍入、时区、闭开区间已写明 |
| 4 | 重复提交和并发更新会怎样？ | 幂等键或唯一约束；乐观锁冲突有错误码 |
| 5 | 事务里有没有调外部系统？ | 没有。跨服务写操作走 Outbox 或已说明的补偿 |
| 6 | 个人信息出现在日志、缓存、导出里吗？ | 已分级；这些出口按矩阵处理 |
| 7 | 手工改生产数据要经过谁？ | 有工单、预演、回滚和审计 |
| 8 | 坏了怎么发现，多久能恢复？ | 有追踪号、告警负责人、恢复目标，并且演练过恢复 |
| 9 | 这次发布的制品是哪一个，怎么退回？ | 不可变制品晋级；回滚步骤已写进发布证据 |
| 10 | 哪些门禁被跳过了？ | 没有跳过，或豁免单写了期限、补偿和关闭人 |
| 11 | 管理端或小程序是否只做了服务端检查？ | 端侧第九节里命中的项已勾选 |
| 12 | 需求的验收条件在哪里被验证？ | 追踪矩阵完整，关键场景有人工业务评审 |
| 13 | 回调能否被重放？密码和令牌怎么校验？ | 回调有签名和时间窗；密码是慢哈希；旧会话能失效 |
| 14 | 导入失败能否定位到行？下载链接会不会永久公开？ | 有行列级错误；下载鉴权且有有效期 |
| 15 | 定时任务在多实例下会不会跑两次？ | 有防重；重试不会重复扣款或重复发消息 |
| 16 | 普通列表会不会把归档历史一起查出来？ | 在线接口只查热数据；查归档有单独接口和权限 |
| 17 | 体验版或审核版会不会连上生产接口和商户号？ | 环境隔离；演示开关默认关闭且发版前已验证 |
