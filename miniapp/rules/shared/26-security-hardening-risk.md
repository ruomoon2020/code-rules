# 26 Security Hardening Risk

面向金融、政务、大流量和多平台小程序的企业安全加固。本文不替代后端鉴权、风控、审计和平台审核；小程序侧只做最小可信边界内的防误用、防泄露和可观测配合。

## 构建与调试资源

1. 生产构建禁止发布 source map、未压缩调试包、测试 fixture、mock 数据、内部调试页、灰度白名单明文和审计绕过入口。
2. 构建产物如需保留 source map，必须只上传到受控错误分析平台，禁止随小程序包或 CDN 公开分发。
3. 开发、体验、审核、正式环境的 AppID、域名、支付商户、认证凭据和远端配置必须分离；禁止通过页面参数切换生产能力。
4. 审核临时能力（演示数据、跳过真实支付、灰度白名单）必须默认关闭、可追溯、可验证关闭，并在发版清单中勾选。

## 高风险操作

1. 支付、退款、余额、优惠券、会员权益、实名、地址、权限变更等操作，前端只能做交互与刷新触发，最终状态以后端鉴权、订单/状态机和风控结果为准。
2. 高风险提交必须防重复点击、重复请求和离线重放；需要幂等键时由统一 request / service 层生成或复用，不在页面散落实现。
3. 敏感页面从分享、二维码、scene、web-view 回跳进入时，必须重新走参数白名单、登录态校验和必要的二次确认。
4. 客户端风险信号（设备、环境、来源、异常频率）只能作为后端风控输入，不得作为唯一拒绝或放行依据。

## 第三方 SDK 与数据流

1. 第三方 SDK 引入前必须登记：用途、包体积、平台兼容性、域名、采集字段、初始化时机、用户退出后的清理方式、隐私影响和替代方案。
2. 统计、广告、地图、客服、风控、A/B、推送类 SDK 默认延后初始化；非首屏必需 SDK 不得阻塞 `onLaunch` 或首页首屏。
3. 第三方 SDK 不得采集认证凭据、手机号、身份证、详细地址、精确位置、支付凭证、未脱敏平台身份标识等敏感字段。
4. SDK 版本升级必须说明隐私、体积、权限和接口行为变化；重大变更须跑隐私、网络、包体积和关键链路回归。

## 远程配置、灰度与实验

1. 功能开关、灰度、实验配置必须有 Owner、默认值、失效策略、回滚方式、观察指标和清理时间。
2. 高风险能力默认关闭；远端配置拉取失败、解析失败、命中异常时必须走安全默认值。
3. A/B 实验须记录实验名、版本、分流口径、互斥关系、命中日志和结束清理计划；禁止长期遗留无 Owner 开关。
4. 审核版、体验版、正式版的实验和远程配置必须隔离；禁止为了审核临时放开正式用户风险路径。

## 跨平台安全边界

1. 微信、支付宝、抖音、快手、QQ 等平台能力差异必须进入 `src/platform/` adapter；页面不得直接用条件编译绕过安全校验。
2. 平台差异矩阵至少覆盖：登录、手机号、位置、订阅消息、支付、分享、web-view、分包、隐私声明、审核限制和包体积阈值。
3. 新增目标平台须补充 `99-project-local.mdc` 的目标平台、域名白名单、隐私能力、支付/订阅限制和验证命令。

## 验证

1. 生产构建须检查 mock、console、调试页、source map、测试账号、硬编码认证凭据、非白名单域名和高风险开关。
2. 涉及第三方 SDK 的 PR 须跑 lint、type-check、build、size:check、audit 或组织等价扫描，并附数据流登记。
3. 涉及实验、远程配置、审核临时能力的 PR 须说明回滚路径、Owner、观察指标和发版后清理计划。
4. 涉及多平台适配的 PR 须列出平台矩阵和不可用能力降级路径。
