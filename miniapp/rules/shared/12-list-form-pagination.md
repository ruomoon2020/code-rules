# 列表、表单与分页规则

## 列表

1. 列表必须包含 loading、empty、error、content、finished 状态。
2. 下拉刷新重置页码和数据；上拉加载只追加下一页。页码字段为 `page`，从 1 开始，禁止 `pageNo` / `pageNum`。
3. 筛选条件变化必须重置页码。
4. 删除最后一条后要回退页码或刷新当前页。
5. 禁止重复触发分页请求。
6. 若列表排序，请求使用 `sortField`、`sortOrder`。`sortOrder` 只传 `asc` 或 `desc`，不把组件的 `ascending` / `descending` 原样提交。

## 表单

1. 字段来自权威契约 `contracts/openapi.yaml` 及其同步生成类型；禁止凭空增加，也禁止手改 `schema.json` 或 generated client 补字段。
2. 必填、长度、格式、枚举、金额、时间必须和后端校验一致。
3. 提交按钮必须防重复点击。
4. 提交失败保留用户输入；成功后按流程返回、刷新或跳转。
5. 并发控制按以下流程处理：
   - 更新和删除请求必须携带页面当前保存的 `version`；提交前不得重新查询详情并替换该值。
   - 收到 `CONCURRENT_MODIFICATION` 或契约声明的等价错误码后，保留用户输入，提示数据已变化，并提供刷新或对比入口。用户确认前不得覆盖提交。
   - 创建成功后保存响应中的初始 `version`；更新成功后以响应中的新 `version` 覆盖本地值，供下一次提交使用。

## 金额、时间与账期

1. 金额字段必须明确币种、单位、精度和舍入规则；禁止用浮点运算计算订单、优惠、券、余额或费率。
2. 展示金额必须使用项目统一 formatter，禁止手写货币符号、`toFixed` 或字符串拼接充当舍入规则。
3. 时刻必须携带时区 / offset 或使用项目声明的 UTC 约定；自然日使用日期类型。禁止用设备本地时区把无时区时间猜成业务日。
4. 自然日、活动截止、券有效期、账期和结算日必须明确业务时区与闭开区间；跨时区或夏令时场景必须有边界测试。

## 移动交互

1. 触控区域要足够大，关键按钮不能贴边。
2. 底部操作区要考虑安全区。
3. 弹窗必须可关闭，授权类弹窗不得阻塞所有路径。
