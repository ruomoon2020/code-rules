# 24 Design System Mobile

移动端与设计系统一致性。页面骨架见 `04`；Base 组件目录见 `01`。

## Token 与样式

1. 颜色、字号、间距、圆角优先使用项目 Token（CSS 变量或 `@/styles/tokens`），禁止页面散落魔法数。
2. 适配使用 `rpx` / 安全区（`safe-area-inset`）；全屏页须处理刘海与底部横条。
3. 暗色模式（若支持）须 Token 切换，禁止硬编码仅浅色。

## 样式架构

1. 原始设计值只有一个来源，主题文件只映射语义主题值。
2. 全局加载顺序固定为基础值与主题、基础样式、工具样式；mixin 和 function 不产生隐式全局 CSS。
3. 组件使用 scoped SCSS 与 BEM 根类；只有基础样式、主题变量、安全区和明确工具类进入全局样式。
4. 嵌套选择器建议不超过 3 层；深层选择器记录第三方边界、影响范围和替代方案。
5. 同时使用原子 CSS 与 SCSS 时固定职责，避免同一属性由两套方案形成隐式优先级。
6. 页面通过 props、slots、CSS 自定义属性或受控 variant 改变 Base 组件，不覆盖内部 BEM 元素。

## 主题管理

1. 设计值分为原始值与语义值，组件只消费语义值。
2. 主题定义默认值和未知主题 fallback；多主题保持同一变量集。
3. 主题由单一 composable 或 store 管理，明确系统偏好、用户选择和服务端配置优先级；持久化版本化且可回退。
4. 切换主题同步页面背景和目标平台原生区域，并避免首屏闪烁。
5. 主题切换只更新主题值与必要平台 UI，不触发业务数据全量刷新。
6. SCSS 变量用于编译期计算；运行时主题通过根节点主题类和 CSS 自定义属性输出。

## BEM 与状态

1. Block 对应组件根节点，Element 表达稳定组成，Modifier 表达外观变体；运行状态统一 `.is-*` / `.has-*`。
2. BEM 类不编码业务数据或节点层级；内部重构时保持对外组件契约稳定。
3. 颜色、间距、字号、圆角、阴影、层级和动画时长使用统一变量。

## 触控与可读性

1. 可点击热区建议不小于 88rpx×88rpx（约 44pt 等价），图标按钮须有可读文案或 `aria-label` 等价说明。
2. 表单错误提示靠近字段；destructive 操作用色与主按钮区分。
3. 适老化 / 系统大字号下布局不得重叠截断（关键页抽测）。

## Base 组件

1. 空态、错误态、骨架屏、加载态使用项目声明的 Base 组件目录，与 `12` 四态一致。
2. 禁止每业务页自创一套样式迥异的按钮/列表空态。
3. 图标字体 / 图片须有占位与加载失败态。
4. Base 组件定义 props、emits、slots、v-model（若有）、variants、状态矩阵、无障碍语义和性能边界。
5. Base 组件不直接调用业务 API、业务 store 或页面路由；跨层上下文使用 typed Provide/Inject。
6. 新增或破坏性修改 Base 组件同步组件文档、测试和迁移说明，不照搬第三方组件 API 制造兼容包袱。

## 组件文档

1. 稳定复用组件提供同目录 README 或组件目录文档，包含用途/非用途、示例、Props、Emits、Slots、v-model、暴露方法、主题变量、状态和限制。
2. 公共 composable 与复杂类型使用 TSDoc 说明前置条件、副作用、清理责任和错误语义。
3. 示例必须通过 type-check，行为变更记录迁移方式。

## 禁止

- 复制粘贴大段 inline style 覆盖全局主题。
- 关键流程仅图标无文字且无无障碍说明。
